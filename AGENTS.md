# Portfolio repository guidance

## Purpose

This public repository contains the website source and deployable configuration for Dan Hughes's portfolio. The private career sourcebook is a separate evidence system and must never be copied or linked into this repository.

Keep the website, README, contributor guidance and public technical documentation self-contained. Never link to the private documentation repository, its files or local checkout paths, including from code comments and generated assets. Private documentation may link to this public repository, never the reverse. Public setup instructions must let readers use their own resources without access to the owner's private records; credential values belong only in the secret store.

## Public-content boundary

- Use British English throughout visible copy, titles, metadata and documentation. Do not use em dashes. Keep required code/API spellings unchanged.

- Use **Observability, SRE & AI Leader** as the prominent homepage headline, with Dan's name secondary. Derive the browser title from the same content value. It is positioning, not a formal employment title; AI refers to hands-on tooling and team engineering practices, not model research or enterprise AI strategy.

Suspend typing and blinking offscreen, when hidden and for reduced motion; reserve all phrase sizes to prevent layout shifts. No separate subtitle pause control, per the owner's request. This is a recorded accessibility compromise, not grounds for a blanket WCAG conformance claim.
- Shuffle through the complete subtitle phrase set before reuse, avoiding adjacent repeats across set boundaries. Keep phrases distinct rather than repeating the same rollout wording. Check motion gates before a queued callback changes text, not only after a preference event.
- Keep SRE and infrastructure primary; AI is supporting evidence rather than a claim of AI/ML security expertise.
- Do not publish employer names, formal employment titles, employment dates or career chronology in copy, metadata, structured data, images, source maps or downloads.
- Do not publish a claim until its exact wording has an approved public-use decision in the private sourcebook.
- Never infer personal ownership, adoption, scale or outcome from platform access or team activity.
- The recorded profiling publication check distinguishes authentication failures from transient upstream errors. Do not describe it as an unconditional guarantee that live rules precede every publication; the private source account records a fail-open exception.
- Use a personal homepage, `/notes/` for engineering depth and `/experiments/` for optional experiments. Main navigation labels are single words: Notes, Experiments, Contact. Do not impose a single-page layout, three evidence entries or an application-form structure.
- Lead with concrete engineering decisions and personality, not abstract business slogans. Personal interests must be sourced; never invent hobbies or favourites.
- Browser-local simulations must be clearly synthetic, keyboard usable and optional. The Radar atlas is separately labelled observed data. Never fabricate production telemetry, terminal output or operational status.
- The Internet atlas automatically requests Radar on initial load and refresh. Its Traffic, Bots, Devices and Protocols tabs share country selection and source metadata. Missing readings are gaps; reported disruptions must not be inferred from traffic dips. Failures clear readings without substituting samples. Initial and no-script views show an empty chart, never a sample that flashes before live data. Reserve interactive geometry before module initialisation. Keep the Radar token server-side and retain the owner's recorded licence decision, attribution and reuse notices.

Expiry and token IDs belong in the vault, not this repository. Development stays Access-protected and non-indexable at `dev.danhughes.uk`; production publication at `danhughes.uk` is approved. Promote through a reviewed `develop` to `main` PR with `PRODUCTION_DEPLOY_ENABLED=true`, never a direct upload or required-check bypass. Verify actual deployment state rather than inferring it from configuration.

The selected-country pulse loops gently while visible, suspends offscreen/hidden and respects reduced motion. There is no page-level background-motion button, per the owner's request. It is a selection cue, not a ping or measured activity.

Reuse validated responses only within its window; do not describe that as upstream freshness. Keep foreground priority, identical-request coalescing, exploration/visibility/connection-hint gating and document-level speculative backoff. Worker unavailable responses, including upstream 502, stop speculation across country/view keys while explicit foreground retry remains usable. Loading/unavailable placeholders are distinct from N/A null readings; source timestamps and Worker limits remain authoritative.
- Omit absent Radar confidence from visible metadata. Preserve null in the data contract, and continue showing supplied confidence ratings and source-quality warnings in every view.

Other offscreen reveals must not affect content already in view. Preload local fonts and avoid late font swaps that shift readable content. Use authored SVGs for prominent arrows rather than emoji-prone text glyphs. Include iPhone 17 Pro-sized WebKit checks without claiming physical Safari testing.

Preserve the separate viewport-gated artwork animations; test direct experiment links without disabling motion or waiting out the movement.

- Keep the homepage connection graphic distinct from Experiments. It is abstract, browser-local geometry, not telemetry. It pulses continuously from different nodes while visible, with one animation-frame chain and no adjacent automatic origin repeat. Stop offscreen/hidden, on page suspension and for reduced motion; resume only when active. Touch entry and non-visible focus keep the complete static mark, with immediate native first-tap home navigation. Reduced motion shows the complete static mark.

- Keep private evidence labels, internal URLs, identifiable incidents and employer-derived assets out of Git and generated output.

## Secrets

- Use reusable, account-level Access policies attached to the development hostname application. Do not recreate application-scoped legacy policies or switch the WebSocket service to Worker-level Access. Review policy references before cleanup, preserve the owner-only rule and verify both anonymous rejection and authenticated operation after changes. Access administration stays outside website CI.
- Never commit or print API tokens, service credentials, Turnstile secret keys, private contact routing or values from `.env` and `.dev.vars` files.
- Keep `.env*`, `.dev.vars*`, Wrangler local state and generated output ignored. An `.env.example` may contain key names and safe descriptions only.
- Use environment-scoped GitHub secrets or Cloudflare secret bindings for deployment and runtime credentials.
- A variable exposed to Astro client code is public. Do not put a secret in a public-prefixed variable.
- Pull-request workflows must not receive production credentials.
- If a credential is committed, rotate it immediately; deleting it from the latest revision is not remediation.

## Engineering expectations

- Review content, visual hierarchy and interaction as one unit. Every featured project must identify Dan's supported contribution, a specific decision and its qualitative consequence; a tool list or anonymous project description is insufficient.
- Explanatory diagrams must explain the adjacent engineering decision. Label conceptual demonstrations and never imply that synthetic traces are production evidence. The decorative homepage connection field is a separate abstract accent, not a career-evidence diagram.
- Note-preview links share a consistent hover and keyboard-focus response, with restrained motion inside the graphic and static captions. Respect reduced motion, avoid sticky touch hover and keep first-tap navigation working. Non-interactive diagrams within notes should not mimic clickable previews.
- Light and dark palettes are both designed states. Support system preference, an explicit persistent override, reduced motion, keyboard controls and no-JavaScript fallback; test every primary route in both palettes.
- Use an icon button for theme selection, not a dropdown. Its icon and accessible label must describe the selected preference, including system mode; state the next action in the label.
- External Hello/Contact links open in a new tab with an accessible new-tab description and `rel="noopener noreferrer"`. Internal Contact navigation remains in the current tab.
- The Experiments "Explore the source" link follows the same protected new-tab convention.
- The shared footer's View source link also opens a protected new tab and describes that behaviour accessibly.
- The shared footer reads "Always tinkering." Notes and Experiments use the same `page-intro` heading treatment, with natural wrapping rather than forced heading breaks. Notes has no Back home links; retain home navigation through the shared mark and footer identity, and keep its closing Connect action.
- The shared `page-intro` owns the divider below Notes and Experiments introductions. Do not add a second border to Notes content. Both content areas begin with the shared section spacing.
- Typography uses the shared body, display and monospace families, weight tokens, and body/reading/small/caption/micro size roles in `global.css`. Do not reintroduce near-identical one-off UI text sizes or an undefined body-font token. Fluid editorial headings, the terminal subtitle and diagram-space text retain purposeful sizing; the terminal heading uses monospace, not the display face.
- Keep the theme control visually unframed and subordinate to navigation, with a small icon inside a full 44 px touch target.
- Accessibility includes keyboard behaviour and assistive-technology semantics, not only an automated score. Verify skip-link focus, visual/DOM order, landmarks, heading hierarchy, meaningful control values and concise link names. Prefer native elements; add ARIA only for information they do not already expose. Do not announce animation frames to screen readers or claim VoiceOver/NVDA testing without actually running it.
- Functional tests are necessary, not a design verdict. Inspect complete sections visually and ask whether the work distinguishes Dan without generic superiority claims or unsupported ownership.
- Reflow checks must cover actual section containment, inter-section gaps and numeric labels, not only document overflow. Do not use percentage row gaps in intrinsic-height stacked sections; keep index numbers unbroken.
- Browser tests must account for fractional DOMRect rounding without tolerating visible overlap. Do not assume wheel input gives an exact scroll distance or that a fresh media query proves existing preference listeners have updated. Assert the relevant layout, focus and motion state across every configured engine.
- Use the shared spacing and responsive heading tokens in `src/styles/global.css` for route rhythm and proportionate typography. Keep readable body copy, illustration aspect ratios, stable experiment frames and touch-target minimums as purposeful exceptions. The decorative homepage connection field keeps one authored asymmetric arrangement across reloads; preserve its fixed frame, no-JavaScript fallback and reduced-motion presentation. Randomise pulse origins, not node positions. Do not restore random layout selection or the network's heartbeat glyph, or confuse it with the separate dh signature mark.
- Keep the homepage connection graphic a compact accent. Note-preview artwork shares a compact size scale, including the leadership typography; allow enlarged text to grow rather than clip. The faint background grid follows both palettes across every route and disappears in forced colours or increased contrast.

## Git workflow

- Keep the public README concise: identity, stack, local commands, checks and honest delivery state. Detailed operational history and QA records do not belong in the introduction.

- Feature branches target `develop`.
- Dependabot version updates target `develop`, with coupled Cloudflare packages grouped separately and major migrations reviewed individually. Security updates still target GitHub's default branch; handle fixes through the verified development and production promotion path, and keep the default branch's Dependabot configuration current.
- `develop` is the persistent development environment.
- Production promotion uses a pull request from `develop` to `main`.
- Do not push directly to protected branches, force-push or bypass required checks.
- GitHub automatically deletes merged PR branches. After each merge, fetch and prune remote-tracking refs, then remove the corresponding local branch once its work is confirmed in the intended target. For squash merges, verify the merged PR head and content rather than relying only on ancestry. Preserve `main`, `develop`, open-PR branches, branches used by another worktree and any unmerged changes. Branch cleanup is part of completion, not a later task.
- The required `quality` job always reports a result. `scripts/ci-changes.mjs` skips expensive steps for recognised documentation-only changes; unknown paths, site content, assets, tests and configuration require the full gate. Development deployment requires the job's `code` output. Do not use workflow-level PR path filters that leave required checks pending. Failed change detection must fail the required job.
- Documentation-only runs retain redacted secret scanning. Workflow concurrency uses `queue: max` with cancellation disabled, including PR runs, so a later docs-only push cannot discard a pending code deployment. The pinned actionlint lacks this field; retain only the exact diagnostic exception in `.github/actionlint.yaml` until upstream support lands. Verify the final deployed SHA after a burst of pushes; queue order is not commit order.
- Keep deployment workflows least-privileged and pin third-party actions to reviewed commit SHAs.
